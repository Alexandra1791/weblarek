# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В этом разделе описаны интерфейсы и типы данных. 

#### Интерфейс IProduct
Описывает структуру данных одной карточки товара, получаемой с сервера.
  interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

#### Интерфейс IBuyer
Описывает структуру данных покупателя.
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}

#### Типы

`type TPayment = 'card' | 'cash';` - описывает доступные способы оплаты заказа.
`type FormErrors = Partial<Record<keyof IBuyer, string>>;` - описывает структуру объекта ошибок валидации форм. Ключами являются поля формы, а значение - текст ошибки.

### Модели данных (Классы)
Классы этого слоя отвечают за хранение информации, ее изменение и предоставление бизнес-логики для других частей приложения.

#### Класс CatalogData (Каталог товаров)

Конструктор:
`constructor()` - создает пустой список товаров и закрывает просмотр карточек. Работает без настроек.

Поля класса:
`protected items: IProduct[]` - хранит массив всех товаров, доступных для покупки.
`protected preview: string | null` - хранит идентификатор (`id`) товара, выбранного для отображения в модальном окне.

Методы класса:
`setItems(product: IProduct[]): void` - берёт список товаров из интернета и сохраняет его в проект. Ничего не возвращает.
`getItems(): IProduct[]` - выдает сохраненный список товаров, чтобы показать его на главном экране. Возвращает список товаров.
`getProduct(productId: string): IProduct | null` -  находит один нужный товар в списке по его ID. Возвращает найденный товар(или ничего, если такого ID нет).
`setPreviewId(productId: string): void` - запоминает, на какой товар нажал пользователь, чтобы открыть его. Ничего не возвращает.
`getPreviewId(): string | null` - возвращает идентификатор (`id`) выбранного для просмотра товара.
`getPreviewProduct(): IProduct | null` - выдает тот самый товар, который пользователь выбрал для просмотра. Возвращает выбранный товар.

#### Класс BasketData (Корзина)
Класс отвечает за хранение товаров, которые покупатель отложил для покупки.

Конструктор:
`constructor()` — делает корзину изначально пустой. Работает без настроек.

Поля класса:
`protected items: IProduct[]` - список товаров, которые лежат в корзине.

Методы класса:
`getItems(): IProduct[]` - выдает список всех товаров, которые сейчас лежат в корзине.
`add(product: IProduct): void` - добавляет выбранный товар в корзину. Ничего не возвращает.
`remove(productId: string): void` - убирает товар из корзины по его ID. Ничего не возвращает.
`clear(): void` - полностью опустошает корзину. Ничего не возвращает.
`getTotal(): number` - считает общую стоимость всех товаров в корзине и возращает итоговую сумму.
`getCount(): number` - считает и возвращает общее количество товаров  в корзине.
`hasProduct(productId: string): boolean` - проверяет, лежит ли уже этот конкретный товар в корзине. Возвращает true/false.

#### Класс OrderData (Покупатель)
Класс собирает данные покупателя (адрес, телефон, почту, способ оплаты), проверяет их на ошибки и хранит до отправки заказа.

Конструктор
`constructor()` - создает чистую анкету покупателя, где еще ничего не заполнено.

Поля класса:
`protected buyer: IBuyer` - анкета с данными покупателя (оплата, адрес, телефон, email).

Методы класса:
`setField(field: keyof IBuyer, value: string): void` - сохраняет текст в конкретную строку анкеты, не стирая при этом остальные заполненные поля. Ничего не возвращает.
`getBuyerData(): IBuyer` - отдает всю заполненную анкету покупателя целиком.
`clear(): void` - полностью стирает всю анкету и сбрасывает список ошибок. Ничего не возвращает.
`validatedata(): FormErrors` - проверяет, чтобы ни одно поле в анкете не осталось пустым. Если находит пустое поле, возвращает текст ошибки для него.

### Слой коммуникации
Классы этого слоя отвечают за организацию взаимодействия между моделями данных приложения и внешним сервером.

#### Класс AppApi
Обеспечивает обмен данными с сервером для получения каталога товаров и отправки оформленных заказов.

Конструктор:
`constructor(baseApi: IApi)` - принимает объект, соответствующий интерфейсу `IApi`, для выполнения HTTP-запросов.

Методы класса:
`getProducts(): Promise<IProductResponse>` - выполняет GET-запрос к эндпоинту `/product/` для получения  полного объекта с массивом товаров с сервера. Возвращает промис с объектом, содержащим список товаром и их общее количество.
`postOrder(orderData: IOrderRequest): Promise<IOrderResult>` - выполняет POST-запрос к эндпоинту `/order/` для отправки данных о покупателе и выбранных товарах на сервер. Возвращает промис с подтверждением успешной покупки(ID заказа и итоговая сумма).
